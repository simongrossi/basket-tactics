## Décisions de design notables

### B1 (Mismatch + scram)
- **Algo basket-correct** : tie-break côté porteur quand les severities
  sont égales (D5 sur O1 = menace immédiate vs D1 sur O5)
- **Métrique sur le pire mismatch**, pas la somme : un trade 4 → (2, 2)
  est un succès

### B3 (Hard vs soft hedge)
- **Séparation propre des axes** quality (offense) et aggression (défense)
- Le `blendFactor = q × hedgeAgg` garantit qu'un écran fantôme reste
  fantôme même en hard hedge

### B2 V2 + B4 V2
- **Modification minimale** : on n'invente pas de nouvelle logique de
  couverture. On force `screen=null` (B2) ou `quality=90` (B4) dans le
  contexte. Les couches en aval (`baseTargets`, `applyScreenAdjustment`)
  réagissent naturellement.

### Multi-sélection (#4)
- **State éphémère** : `selectedDefenders: Set<DefenderId>` dans CourtView,
  pas dans `AppState`. Pas de persistance, pas d'undo individuel.
- **1 entrée undo pour drag groupé** : réutilise le pattern existant
  `beginPlayerDrag` / `moveDefenderDuringDrag` / `commitPlayerDrag` qui
  coalesce naturellement.

## Conventions ressorties pendant la session

- **Refactoring** : un fichier ≥ 700-800 lignes avec plusieurs domaines
  distincts est candidat au découpage. Patterns documentés.
- **Nouvelles features défensives** : opt-in via setting `state.*` pour
  ne pas casser les scénarios sauvegardés.
- **Tests d'intégration** : vérifier le pipeline complet via
  `effectiveDefensePositions(state, stepIdx)`, pas juste les helpers.
- **V1 diagnostic-only → V2 réaction** : pattern explicite pour les
  détecteurs complexes (B2, B4). Permet de valider la détection avant
  d'impacter la défense.
